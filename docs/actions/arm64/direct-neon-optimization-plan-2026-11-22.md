# Direct Neon optimization investigation on Mac M2

Prepared 22 November 2026 for a future session. Start with the FP32 cross-product blend. It is a one-pattern library change whose effect can be checked in an existing optimized caller. Evaluate each candidate independently.

The source review used master `88c48689f1ec4d6fa665df6a9c6b41a3d064bb0a`. The retained timings belong to `dc802e466663d61d9e219bd7c7351aa8ac312204`, Apple M2, Apple Clang 21 and SDK 26.5. Direct Neon led in 43 of 160 rows and fell within the 5% comparison band in the other 117. These figures identify targets. Each experiment needs its own matched control. ## First experiment — FP32 AoS cross product

1. **Reproduce the caller.** Inspect the Release assembly for the FP32 AoS `vec3_cross` loop at the selected control commit. The retained build has four single-table lookups for the input permutations and a fifth, two-table lookup after the subtract for `blend4<0,1,2,7>(c, zero)`. Direct Neon measured about 0.62 ns per cross product at both 128 and 4,096 objects. If the current compiler already emits a lane clear, close this hypothesis at inspection. [Caller](../../../benchmarks/arm64/kernels.cpp) · [Retained Clang 21 disassembly](../../../build/mat4-vector-clang-study-2026-11-21-20261121T084549263495Z/c21-sdk265-neon-disassembly.log)
2. **Try one specialization.** In the Direct Neon four-lane blend helper, express this exact pattern as copying lane 3 of the second input into lane 3 of the first. Preserve the first three lanes and copy all 32 bits of the fourth for arbitrary inputs. Check distinct integer bit patterns, signed zero and NaN payloads, including a nonzero fourth lane from the second input. Preserve FP exception behavior and the existing arithmetic order. Inspect the optimized caller again for the final lane instruction, index constant loads and any new spills. [Blend implementation](../../../vectori128_perm_neon.h)
3. **Measure the tradeoff.** Compare fresh control and candidate builds on the same M2 with the same compiler, SDK, flags, fixtures and seeds. Time Release serially using the retained protocol of three invocations per backend/count and nine trials per shape. Record medians, ranges, output bits and all slower rows. Target FP32 AoS cross at 128 and 4,096 objects. Watch FP32 AoS transpose and TRS inverse at both counts, and FP32 SoA dot at 4,096 objects at widths 128 and 256. The earlier inverse candidate recorded a 12.4% dot cost in one matched session. [Timing protocol](../../benchmarks/arm64/standard-math-master-2026-11-21/protocol.json) · [Prior decision](../../validation/arm64/trs-inverse-decision-2026-11-20.md)
4. **Decide.** Advance only if the caller improves, repeated cross timings show a gain distinguishable from variation, and neighboring workloads have no material regression. If the result is inconclusive, record it and retain the control. For a promising runtime candidate, verify the pinned dependencies and protected originals, freeze the exact source and run the full native M2 correctness matrix separately from timing. Cover compatibility 512 and Direct Neon 128/256/512 in Release and strict nonrecovering UBSan Debug, with 60-second case deadlines and concurrency three. The reviewed inventory was 8,036 cases plus eight arithmetic smokes. Review the full 160-row matched Release suite before recommending integration.
